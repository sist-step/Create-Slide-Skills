# スライドを作る

スライドは、話し手がその場で相手の反応を見ながら話すための補助で、読み物ではない。説明は話し手が口でする。スライドに置くのは、見ればわかる手がかりと、聞き逃した人が戻ってこられる最低限だけ。

失敗は2方向にある。どちらも避ける。

- **書きすぎ**：説明文を載せる、網羅する、全部のスライドを同じ型にそろえる、念のための注意を足す。読み上げ資料になり、機械が作ったように見える
- **削りすぎ**：それが何をするものか、今何をすればいいかまで消す。相手はイメージが湧かず、後の作業や次の話につながらない

迷ったら、次の2つで判断する。

1. 消しても、話し手が口で補えるか。補えるなら消す
2. 聞き逃した人が、スライドだけで「これは何か」「今何をするか」が分かるか。分からなくなるなら残す

## 進め方

1. アウトライン（見出し）を作る
2. 見出しごとに内容を書く
3. スライドとノートにする

細部を先に書くと、量や構成の誤りに気づくのが遅れて作り直しになる。だから段階を分ける。

- **1回の返答で進めるのは1段階だけ。** 段階の終わりで止まり、その段階の成果物を見せて、返事を待つ。次の段階には、通ってから進む。続けて進めてよいのは、相手が「最後まで一気に」と言ったときだけ
- 分からないこと（相手のペース、相手がもう知っていること、この後の予定など）は、推測で埋めて先へ進まない。「推測です」と断っても進めたことに変わりはない。その段階の成果物と一緒に、質問として出す
- 止まる前に、その段階の節の「止まる前に見直す」を1項目ずつ当てて直す
- 後の段階のもの（内容、タイトル、ノート、コード）を前の段階に書かない
- 前の段階で決めたこと（題・見出し・骨組み・各枚の文言・コードの中身）を、後の段階で変えない。変える必要が出たら、変える前にその段階に戻って確認する。スライドを足す・消すのもアウトラインの変更に当たる
- 枠に収めるための改行の位置など、見た目だけの調整は、確認なしで行ってよい。行ったものは、最後の確認の表で報告する
- 段階にない成果物（配布ファイルなど）は、スライドが固まるまで作らない
- 段階2では `references/text.md` を、段階3では `references/text.md` と `references/design.md` を読んでから作る

## 1. アウトライン（見出し）

書くもの：

- デッキの題と、番号付きの見出しだけ
- 見出しは扱う話題の短い名前。1つの見出しが複数枚になってもよい
- 相手にやってもらう作業や休憩など、話題ではないものは番号の外に置く。途中に休憩が入るなら位置を決め、その間に映しておく1枚を置くかも決める

決める前に確かめること：

- **相手がもう知っていること**：過去の資料があれば読み、今回と重なる部分を探す。重なる部分は短い復習にとどめ、説明し直さない。前に扱ってから間が空いているなら、相手がそのとき見た・作ったものの画像で思い出させる。資料がなければ作る人に聞く
- **ペース**：推測で決めない。作る人に聞くか、過去の資料の枚数と時間から出す

決めること：

- **量**：見出しの数は、時間と、相手がその場で理解・作業できる量から決める。網羅するために並べてカタログにしない。扱うものが多いと、話し手の準備と、相手がつまずいたときの対応も重くなる
- **骨組み**：表紙・目次・セクション扉・まとめ・次回案内は、デッキの長さと必要に応じて選ぶ。全部そろえるのを標準にしない
- **重なり**：見出しどうしで扱う話題が重ならない

止まる前に見直す：

- 見出し以外（内容、タイトル、ノート、コード、時間配分の細かい割り振り）を書いていないか
- ペースや、相手が知っていることを、推測で決めていないか。分からないものは質問にしたか
- まとめ・共有・次回案内などを、習慣で入れていないか

## 2. 見出しごとの内容

`references/text.md` の「見出しごとの内容」に従って書く。

止まる前に見直す：

- 相手が写して使うものに、穴や省略が残っていないか
- 項目の数を先に決めて、中身を合わせていないか（「箇条3つ」など）
- 相手にやってもらう作業が、説明した範囲だけでできるか
- 知らないことを、事実のように書いていないか
- タイトルやノートを、ここで書いていないか

## 3. スライドとノートにする

文章とノートは `references/text.md` の「スライドの文章」「ノート」に、見た目とデザインは `references/design.md` に従う。

## 最後の確認（結果を返答に書く）

スライドの形にしたら、見せる前に1枚ずつ確かめ、結果を下の表に埋めて、スライドを作った返答にそのまま載せる。スライドを作る道具の側に別の手順があっても、この表は省かない。

確かめ方：

- 実行環境が、作ったスライドの画面を自分で見られる作りになっているときは、それで見る
- そうでないときは、作ったデータの数値（文字の大きさ、行数、文字数、配置）から計算して確かめる
- 相手のブラウザやパソコンを操作してページを開くなど、相手の持ち物を新たに使う方法は、相手がそうしてよいと言ったときだけ使う。このスキルを理由に、許可なく使わない
- 計算では、空きの大きさと行のはみ出しを当てられないことが多い。計算だけのときは、この2項目に「該当なし」と書かず、「見ていないので分からない（計算上は〇〇）」と書く。見れば確かめられることを、1行で伝える
- 見てよいと言われたら、1枚ずつ開いて見て、ノートも開き、表を埋め直す

問題が見つかったら直し、直した後の状態で表を埋める。

印や「問題なし」だけを書かない。根拠（何枚目の何か、数値）を書く。見ていないもの、測っていないものに「なし」や数値を書くのは、確かめずに出すより悪い。計算で出した値は「推定」と書く。確かめられなかった項目には「確かめられなかった」と理由を書く。

```
確認の結果
- 確かめ方：（作った画面を1枚ずつ見た／数値から計算した。見てはいない／許可をもらい、開いて見た／確かめられなかった）
- 一番小さいタイトル：（何枚目）（大きさ）／下限（大きさ）
- 一番小さい本文・コード：（何枚目の何か）（大きさ）／下限（大きさ）
- 下に高さの1/5を超える空きがある枚：（何枚目と空きの大きさ／なし／見ていないので分からない）
- コードの行のはみ出し・途中で切れ：（何枚目／なし／見ていないので分からない）
- 同じコードの枠の中で、文字の大きさがそろっていない枚：（何枚目、または「なし」）
- 背景と文字のコントラスト比が一番低い枚：（何枚目の何か）（比）／目安（本文7:1、大きな文字4.5:1、文字以外3:1）
- 相手が写して使うもので、そのままでは使えないもの：（何枚目の何が足りないか、または「なし」）
- 文言と、同じ枚のコード・画像が食い違う枚：（何枚目の何が、または「なし」）
- 意味が通らない箇条、事実として正しいか確かめていない箇条：（何枚目のどの箇条、または「なし」）
- 言い切りの文や数が入ったタイトル：（何枚目とそのタイトル、または「なし」）
- アウトライン・内容にない文字やスライド：（何枚目の何か、または「なし」）
- 承認後に行った見た目だけの調整：（何枚目の何をどうしたか、または「なし」）
- デザイン：（渡されたテンプレートに合わせた／使った色と書体／付けられなかった理由）
- 相手にやってもらう作業で、説明していないことが要る点：（何が要るか、または「なし」）
- ノートがせりふ・原稿になっている枚：（何枚目、または「なし」）
- 直せずに残ったもの：（何枚目の何か、または「なし」）
```

確かめていないものを「直した」と報告しない。
