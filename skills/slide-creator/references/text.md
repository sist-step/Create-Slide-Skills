# 文章とノート

## 見出しごとの内容

見出しごとに、何枚にするかと、1枚ごとに載せるものを書く。載せるものは、箇条・図や画像・コードなど。画像と口頭で足りるものは「省略」とだけ書く。画像の上の小さな見出しや表の見出しなど、載せる文字はここで決める。

内容は、その見出しの話題の範囲だけにする。「そのときに起きること」という理由で、別の話題を入れない。新しい話題が要るならアウトラインに戻る。

必ず分かるようにするもの：

- 新しく出てくるものは、何をするものかを1行で書く。使い方だけを書くと、相手は何のための手順か分からない
- そのスライドの要点を1行で置くのはよい

書かないもの：

- 口で言えば済む理由や言い換え
- 画面・コード・図で見せられるものの文章での説明
- 話題を入れ替えてもそのまま成り立つ文（抽象的で、そのスライド固有の情報がない）
- 読んだ人がそれを見て行動を変えない固有名詞・用語・正式名称
- 相手が今回の作業で実際には困らない注意点。つまずく点が分からないときは足さず、作る人に聞く
- 話をつなぐためだけの文。足す前に、その文が事実として正しく、同じスライドのコードや図と合っているかを確かめる
- 相手がまだ知らないことを前提にした言い方（説明していないものとの対比など）。必要な補足は口頭に回す

見せるもの：

- 動きや見た目が要点のものは、実際に動いている様子（動画・動く画像・画面）で見せる。文章で形容しない
- 新しいものをいくつか紹介するときは、個別の説明の前に、実際に使われている様子と名前だけを見せると、相手が先にイメージを持てる。ただし、後で相手にやってもらう作業の完成形をそこで見せると、目標が大きく見える。別のものを使う

書き方：

- 箇条は少なく。1項目は1〜2行。文末に句点を付けない
- 抽象的な文は、具体的な中身に置き換える。抽象の後ろに具体を足して文を増やさない
- 項目数を先に決めない。項目の分量や形を無理にそろえない
- 1つの内容は1枚にだけ置く。復習やまとめ、問いを見せたまま答えを足した複製スライドなど、意図して繰り返すものは残す
- 同じことをする方法が複数あっても、違いを伝える目的がなければ1つに統一する（読み込み先、書き方、バージョンの指定など）
- 相手が写して使うもの（コード、コマンド、URL、設定など）は、そのまま使える形にする。「…」や「（ここにURL）」のような穴を残さない。長くて入らないときは、要点の部分だけを載せて全体は配布物やリンクに回す。一部だけ載せるときも、載せた部分がそのまま書ける形にする（種類の違うコードを、囲むタグなしで1つにつなげない）。長いURLなどは途中で折り返さず、行の分け方を変えて収める
- 相手にやってもらう作業（演習、課題、ワークなど）は、そのデッキで説明した範囲だけでできるものにする。説明していないことが要るものは、発展として分けるか、アウトラインに戻って説明する
- ファイル名やフォルダ名を載せるなら、実際の配布物と一致させる。まだ決まっていないものは書かない

## スライドの文章

- 内容をそのまま載せる。この段階で文や文字を足したり、説明文にのばしたりしない。アウトラインにない区切り・セクション名・副題も足さない
- タイトルは、載せるものを見てから付ける。先に付けると、中身がタイトルに合わせて膨らむ。問いか名詞で止め、主張を言い切る文にしない（「〇〇すると、〇〇になる」の形も言い切りの文）。本文と同じことを言わない。「〇つのこと」のような数を入れない
- タイトルや箇条の言うこと（量・行数・手順の数、簡単さの程度）を、同じスライドのコードや画像と一致させる。コードの行を分けた結果、「1行」などの文言と合わなくなったら、文言のほうを直す

## ノート

- 話す原稿にしない。話し手は相手の反応を見ながら進めるので、書いた文章のとおりには話せない。何を主に話すかが分かれば足りる
- 言うことは、体言止めなどを使った短い文で数行。かぎ括弧に入れたせりふにしない。スライドを見れば分かることは書かず、スライドにない情報（理由、何も指定しないときの値、前に話したこととの関係など）を書く
- やること（実演、操作、見せるもの）は、言うことと見分けがつくように括弧に入れる
- 表紙は、挨拶と題の読み上げ程度でよい
- ノートも、事実・同じスライドのコード・配布物と一致させる。相手がまだ知らないことを前提にしない。分からないこと（この後の予定など）は書かない

## 書き換えの例

1枚の文章がどれだけ減るかの目安。書き換え後の言い回しや記号の使い方をまねない。

前：
```
ライブラリを使うと、作りたいものに時間を使える
[時計] 時間が節約できる
  難しい部分を一から作らなくていいので、デザインやアイデアに時間を回せる。
[トロフィー] クオリティが上がる
  世界中で使われ、何度も改良されてきたコードなので、動きがなめらかで見た目もきれい。
[ロケット] できることが広がる
  グラフ、スライドショー、ゲームなど、自分だけでは難しい機能も作れる。
```

後：
```
- 難しい部分を作らなくていい
- 1人じゃ大変な機能も作れる
（ライブラリで作った実物の画面）
```
動きや見た目のきれいさは、実物を見せて口で言う。
